## 二、问题清单（按严重程度）

### 高（2 项）

| # | 问题 | 影响 |
|---|---|---|
| H1 | **大厅 / 摊牌阶段断线即删 token 移出房间**。`handleDisconnect` 不区分阶段，一律 `removePlayer` → `tokens.delete` | 与「token 可 resume 回原座位」的设计直接冲突：**刷新页面就被踢出房间**，对局中闪断同理 |
| H2 | **无心跳探活 + 客户端不自动重连**。半开连接（笔记本合盖、Wi-Fi 掉线不发 FIN）服务端永远认为人还在；而掉线托管只覆盖 `ws === null`，连线中挂机的玩家**没有回合超时兜底** | 对局中一次网络抖动 = **全桌永久等待**（牌不推进、无任何提示），且客户端只弹「请刷新页面重连」，必须手动操作 |

### 中（5 项）

| # | 问题 | 影响 |
|---|---|---|
| M1 | **不足 4 人也能定庄**。原判定 `dealerRolls.length === players.length`，3 人时即结算庄家 | 后到的人没机会掷骰；且与「未定庄不能开局」的门禁设计相悖 |
| M2 | **静态服务 MIME 表缺 `.webmanifest`**，以 `application/octet-stream` 下发 | 浏览器可能拒绝解析 manifest → **安装到主屏后系统级强制横屏失效**（iOS 上唯一的自动横屏途径） |
| M3 | **断线宽限期届满撞上「牌局进行中」会 `forceOver` 中止牌局** | 一个人掉线超 30s，另外三家正在打的牌局被强行结束 |
| M4 | **合法但迟到的动作被报错**。玩家点「胡」时对局仍在进行，消息到达时同炮已被他人先胡 → `assertPlaying()` 抛「本局已结束」 | 一炮多响时落选者看到误导性错误提示，以为是自己操作有问题 |
| M5 | **矮桌面视口对局视图 9~23px 纵向溢出**。`#table` 高度预算常量 225px 少算了页头块（实测页头 61 + 视图 chrome 173 = 234px） | 1366×768 / 1440×720 / 1280×720 / 1280×600 / 900×500 / 800×600 六个常见矮桌面出现滚动条 |

### 低（4 项）

| # | 问题 | 影响 |
|---|---|---|
| L1 | **并发应答竞态误报**。窗口已被他人结算时 `respond()` 抛「当前没有可响应的出牌」 | 弹无意义错误提示 |
| L2 | **`connectAndSend` 在 CONNECTING 态另开连接**。两条连接各发一次（resume + create/join），服务端把第二条判为「你已经在房间里了」 | 用户点创建/加入却**静默回到旧房间** |
| L3 | **事件 feed 永不裁剪**。`addFeed` 只 prepend 不设上限（聊天记录有 200 条上限，feed 漏了） | 长时间蹲一个房间（多局连打 / 异常刷屏）DOM 节点无限堆积；实测一次异常刷屏即产生 3 万个 `<li>` |
| L4 | **文档索引路径失真**。README 声称 `docs/README.md`、`docs/guides/agent.md`，实际索引就是根 README、`agent.md` 在根目录、`docs/guides/` 不存在 | 文档跳转全部落空，违反「引用一律写相对路径」的约定 |

### 观察项（不修，附理由）

| # | 现象 | 判断 |
|---|---|---|
| O1 | 强制横屏退出钮与画布顶边重叠 44×5px（逻辑坐标） | 落在画布最上沿的桌面边框区（非牌面 / 铭牌交互区），`mobile_exit_btn_check` 的 `blocksNothing` 属保守判定（任何与可点元素的重叠都算）。该区域布局有历史裁剪事故记录，**改动风险大于收益**，不动 |

## 三、修复方案与落地明细

### H1 断线宽限（`packages/server/src/index.ts`）

- `Player` 新增 `reconTimer`；新增 `RECON_MS`（默认 30000，可用 `MAHJONG_RECON_MS` 调）。
- `leaveRoom` 拆出 `removePlayer(room, seat)`，新增 `beginReconnectGrace()`：只解绑定、`p.ws = null`、`p.ready = false`，起宽限定时器；期间同房广播「XX 掉线，N 秒内可重连」。
- `handleDisconnect` 分阶段：**对局中 → 托管**（原行为）；**大厅 / 摊牌 → 宽限**。
- 宽限届满时若牌局已在进行 → **直接返回**（修 M3），留待本局结束由 `onGameOver`/`finalizeIfReady` 清理。
- `removePlayer` 摊牌分支补一次 `finalizeIfReady`（否则其余人都点了「下一局」会一直悬着）。
- `resume` / `dissolve` 分支清理 `reconTimer`；`create` / `join` 的字面量补 `reconTimer: null`。
- 客户端：大厅座位卡显示「掉线 · 等待重连」（`.seat-state.offline` 红色）。

### H2 心跳 + 自动重连

**服务端**（`packages/server/src/index.ts`）：

- 新增 `PING_MS`（15000）/ `PONG_TTL_MS`（45000），`lastAlive: Map<WebSocket, number>` 记录最近一次 pong 时间。
- 定时轮询：超 TTL 未回应 → `ws.terminate()`（触发既有 `close` → 掉线托管 + 宽限）；`readyState` 非 OPEN 的条目直接清理。
- 半开连接由此转为「正式掉线」，自动行牌 / 宽限 / resume 全套既有机制立刻生效。

**客户端**（`packages/client/src/main.ts`）：

- 新增 `reconnTimer` / `reconnTries` / `RECONNECT_MAX_TRIES = 10`；`close`  handler 在 `inRoom` 时显示「连接已断开，正在重连…」并进入 `scheduleReconnect()`。
- 退避 1s→2s→3s→4s（封顶），累计 ≈34s，**完整覆盖服务端 30s 宽限还有余量**。
- 凭 `localStorage` 里的 token 发 `resume`；借 `autoResume` 兜底——座位已被回收时回向导并带上房间码。
- 收到任意服务端消息即重置计数、收起横幅；`exitHome` 主动关闭不触发重连（`inRoom` 已置 false）。

### M1 定庄门禁

服务端 `rollDealer` 要求 `players.length === MAX_SEATS` 才接受掷骰，且必须 `players.length === 4 && dealerRolls.length === 4` 才结算；客户端 `#dr-btn` 未满 4 人置灰并提示「等满 4 人（n/4）」。

### M2 MIME

静态服务 MIME 表新增 `'.webmanifest': 'application/manifest+json'`，实测返回正确类型。

### M4 迟到动作静默忽略

`case 'zimo'`（discard / claim / pass / selfGang / zimo 共用入口）在 `room.game.phase !== 'playing'` 时直接 `return`，不再回错误。无对局时仍保留「当前没有进行中的对局」报错（非法操作用例依赖它）。

### M5 画布高度预算

`#table` 宽度公式 `calc(max(0px, 100vh - 225px) * 2)` → `250px`（= 实测需求 234px + 16px 余量吸收状态波动）。移动端有独立的 `html.mobile-layout #table` 规则，**不受影响**。

### L1 并发应答静默返回

`Game.respond()` 无 pending 时返回 `[]` 而非抛错——「过」本身就是「不做任何事」。

### L2 复用 CONNECTING 连接

`connectAndSend` 对 `OPEN || CONNECTING` 一律 `flush()` 后返回，不再另开连接。

### L3 feed 裁剪

`addFeed` 与聊天记录对齐：保留最新 200 条，超出删最旧。

### L4 文档

README 目录结构块改为真实布局；指引表指向根 `agent.md` 并登记本报告；`agent.md` §7 补 `MAHJONG_RECON_MS` / `MAHJONG_PING_MS` / `MAHJONG_PONG_TTL_MS` 三个钩子与断线行为一览。

### 覆盖到的边界情况

- 定庄：3 人掷骰不定庄、补满 4 人后可定、并列重掷、四端庄家一致
- 开局：庄 14 / 闲 13、`wallLeft=83`、赣州海底预留收缩（65）、玩法 id 未知回退南昌、非房主切玩法被拒
- 连接：无效 token 被拒、大厅断线 token resume 回原座位、换位后 resume 回新座位、半开连接判定、自动重连、房主身份随人走
- 聊天 / 表情：60 字截断、控制字符清洗、空白不广播、非法表情 id / 自投 / 非法座位被丢弃、全员广播含自己
- 非法操作：未开局出牌、非自己回合出牌、打没有的牌、服务端不崩、房主解散全员收到

## 七、非缺陷说明与待确认口径

1. **南昌流局不结算**：符合 `docs/rules/nanchang.md`「只在有人胡牌时结算，流局不算」，非缺陷。
2. **赣州「全包胡分」与点炮 / 自摸可能重复计费**（`packHuShare=1`）：已登记于 `docs/integration/ganzhou.md` §8 **F 项待确认**。按「改规则先改文档、两处同改」的铁律，**未擅自改动口径**，留待牌友确认。
3. **连线中但挂机的玩家仍会阻塞牌局**：心跳只解决「连接已死」，不解决「人还在连接却不动」。加回合超时属于**玩法策略**（会自动打出玩家想留的牌），规则文档无此规定，故不擅自引入；当前缓解手段是房主可解散对局。
4. **压测输出里的机器人时序噪声**（「对局进行中，无法准备」等）：测试脚本按固定节奏发消息所致，服务端拒绝是正确的。
