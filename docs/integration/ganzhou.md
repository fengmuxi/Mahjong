# 赣州冲关麻将 · 接入改动说明

> 规则来源：`docs/rules/ganzhou.md`（下称「规则文档」）+ **牌友确认口径（2026-10-15，见 §7）**。
> 本文记录新玩法如何接入既有麻将工程、改了哪些文件、配置项在哪，以及已确认口径与仍待确认事项。
> 南昌麻将（默认玩法）行为零变化；改动后的校验方式见 §6。

---

## 1. 架构定位：新玩法接在哪里

工程既有分层（`docs/architecture/multi-variant.md`）：

```
engine（对局状态机，与玩法无关）  server/game.ts
   └─ RuleSet 契约               shared/src/rules/types.ts
        └─ variants              shared/src/rules/{nanchang,ganzhou}.ts
             registry            shared/src/rules/index.ts（VARIANTS / getRules）
```

P0 阶段已落地「契约 + 注册表 + 房间玩法落库 + 入口玩法卡片」，但**引擎仍是南昌语义**
（`game.ts` 直接 import 南昌的 `analyzeWin / chiOptions / classifyPattern`）。本次接入按
契约精神把赣州差异全部收敛到「一个 RuleSet + 若干纯函数模块」，引擎只加**玩法分支**：

| 规则切面 | 南昌 | 赣州冲关（含确认口径） | 接入位置 |
|---|---|---|---|
| 牌库 / 牌面 | 136 张、34 种 | 相同 | 复用 `tiles.ts`（`rules.tiles` 契路） |
| 字牌成组（乱风） | 三张不同风 / 中发白 | **风、箭各自成组（风箭不混）**：东南西北任意 3 张不同风 / 中发白任意 3 张不同箭 | `gzwin.ts` `gzChiOptions` / 分解器 |
| 精牌模型 | 正精+副精 = 万能牌 | 6 正精+6 副精 = **只结算记分**；**精分含牌河**（打出的精归打出者） | `gzjing.ts` + 引擎翻精分支 |
| 精霸 | 无 | **某组正精+副精独占 → 该组得分 ×2**（按组判定，可多组同时触发） | `gzjing.ts` `gzJingSeatScores` |
| 翻精定位 | 摸牌处逆时针第 S 列上层 | **牌墙尾倒数 S 墩上张**（6 正精 + 6 副精；副精 = 正精的下一张序数牌） | `game.ts` `gzFlip()` |
| 海底 | 无 | **正精墩即预留区前缘**：摸到精墩前缘无人胡 → 流局 | `game.ts` `applyGzFlip()` 截断可摸区 |
| 杠后补牌 | 掷骰定位 / 牌尾 | **掷骰定位：牌墙尾（可摸区尾）倒数 S 墩** | `GZ_CONFIG.gangDice` + `gzLocateTail()` |
| 抢杠胡 | 无 | **有**（补杠被胡） | `game.ts` 抢杠窗口 |
| 胡牌判定 | 赖子通配 + 算子表 | 无万能分解 + 有精限制；**小七对不允暗杠** | `gzwin.ts` `gzAnalyzeWin` |
| 天地胡 | 天胡 / 地胡（宽） | **天和 = 庄起手即胡；地和 = 闲家胡庄家第一张** | `game.ts` `gzBuildWin` |
| 德中德 | 德国 + 三家无精 | **德国 + 任意胡牌牌型（含平胡）+ 其余三家一张精牌都没有** → 胡牌分 ×4 | `gzwin.ts` `gzIsDezhongde` + `game.ts` gzBuildWin |
| 算分 | 算子表 + 逐对点差 | **精分+杠分走四人交叉；胡牌分直付**（自摸三家各付全分 / 点炮者全分+其余各 4） | `gzscore.ts` `gzSettle` |
| 全包 | 无 | 打出精牌被吃碰杠 → 打出者付**杠分 + 整组牌精分**，不进交叉（帮另两位出） | `gzscore.ts` |
| 抄庄 | 无 | **第一轮四家同张手牌 → 庄家给每位闲家 10 分** | `game.ts` 检测 + `gzscore.ts` |
| 霸王精 | 无 | **无此玩法**（确认取消） | — |
| 过水 | 有 | 文档未提及 → 关 | `flow.skipRon=false` |
| 一炮多响 | 并行窗口 + 优先级 | **按逆时针顺序**：近者未应答不结算；近者过才轮到远者 | `game.ts` `respond()` |
| 轮庄 | 庄胡连庄 / 闲胡下家 | **胡牌者接庄** | `server/index.ts` `nextDealer` |

**与原有入口/选择流程的对接（零改动）**：首页第 ② 步「选择玩法」的卡片由
`VARIANT_LIST`（从注册表派生）渲染——`rules/index.ts` 里登记 `ganzhou` 后，卡片自动出现；
创建房间消息已带 `variant`（服务端 `getRules()` 归一，未知 id 回退南昌）；房间页角标、
牌桌视图的 `variant` 字段沿用既有协议。**即：选「赣州冲关麻将」建房即可开局，无需任何客户端改代码。**

## 5. 规则实现要点

1. **精牌纯结算**：不当万能牌、无行牌特权；12 张精按牌面两两配对为 **6 组「正精+副精」**，
   **逐组**按冲关独立计算、相同组合重复累加；一张物理牌只计一次、优先顶正精位（`gzjing.ts`
   `gzJingSeatScores`）。**仅全包（§5.6）**按单张牌面叠加取值（一牌双精 = 3 分）。翻精在牌墙尾定位：正精墩 + 前/后邻墩共 3 墩 6 张
   为正精（仅翻出的那张公开）。
   - **三类精牌（`gzjing.ts` 的 `GZ_JING_CATEGORIES` 为权威定义）**：
     ① **明面正精** 1 张 = 翻出的那张，公开；② **隐藏正精** 5 张 = 正精墩下张 + 前后邻墩各 2 张，
     全程扣放；③ **副精** 6 张 = 每张正精的**下一张序数牌**。三类都**不能当万能牌凑牌型**，
     都按牌面计分（正精 2 / 副精 1）。
   - ⚠️ **副精按「序数下一张」推导，与牌墙位置无关**（2026-10-16 修订）：一万→二万、九万→一万、
     北→东、白→中（见 `tiles.ts` `nextJing()` / `gzjing.ts` `gzFuOf()`）。**不要再按牌墙取牌顺序
     或槽位 ±1 推副精**——那是已废弃的旧口径（2026-10-15 曾修过一版按取牌顺序的，同样作废）。
   - 隐藏正精「即使被摸到也不能当精」在实现上是**结构性保证**：胡牌分解 `gzDecompose` 连 wild
     参数都没有，`gzIsWildcard()` 恒 false；想开通配必须先改这两个入口。
2. **海底（确认口径）**：正精墩即牌墙尾预留区前缘——该墩及牌墙尾方向不再被摸走，可摸张数
   在翻精时一次算清；摸到精墩前缘仍无人胡牌即流局，直接结算精分与杠分。
3. **有精胡牌受限**：暗牌含精 → 只能 ① 精吊（精作将——**将牌 = 1 张精 + 任意 1 张牌**，
   不要求同种精；七对含精对也算）② 特殊牌型
   （小七/大七/十三烂/七星）③ 杠开豁免平胡；**不得平胡**。无精 → 德国（+8），任意牌型。
   「精归位」体现为：精牌被打出或吃碰杠进副露后，暗牌无精即德国。
4. **结算（确认口径：胡牌分和精分分开算）**：
   - **精分 + 杠分 → 四人交叉**（两两 6 笔，恒零和）；
   - **胡牌分 → 直付**：自摸 = 其余三家各付全分（§7.4 示例算术可证）；点炮/抢杠 = 点炮者
     付全分 + 其余两家各 4；
   - **全包**：打出精牌被吃/碰/杠 → 打出者一人付该次杠分 + 整组牌的精分，不进交叉
     （= 帮另外两位一起出）；
   - **抄庄**：第一轮四家同张手牌 → 庄家给每位闲家 10 分；
   - 精分归属：手牌 + 副露 + 牌河（打出无人碰的精归打出者），点炮张归赢家。
5. **抢杠胡**：补杠后开响应窗口，其余三家可胡该牌；有人胡 → 撤回补杠（副露回碰、牌归还、
   不计杠分、不补牌）并按点炮口径结算；无人胡 → 杠成立、**掷骰定位补牌**（牌墙尾倒数 S 墩，
   上层在取上层）。
6. **一炮多响按逆时针顺序**：多人可胡时，近出牌者未应答则不提前结算；近者胡 → 近者赢，
   近者过 → 才轮到远者（两个玩法一致）。
7. **德中德（确认口径）**：赢家**德国**（暗牌无精）+ **任意胡牌牌型**（平胡也算）+ **其余三家
   一张精牌都没有**（按物理持有算：手牌 + 副露 + 牌河；牌墙里的精不算任何人的）→ 胡牌分 ×4。
   判定必须看别家的牌，故放在引擎 `gzBuildWin`（胡型分析只拿到赢家信息），纯函数
   `gzIsDezhongde(german, othersHoldings, jing)` 单测。天地胡按文档只叠精吊/德国，**不叠德中德**
   （见 §8）。
8. **报杠 / 展示三张（§8.5，2026-10-16 新增）**：
   - **开关经 RuleSet 契约**：`FlowConfig.declaredKong`（`rules/types.ts`），仅 `rules/ganzhou.ts`
     置 true —— 引擎 `game.ts` 只认 `rules.flow.declaredKong`，不 import 玩法文件。
   - **协议**：`ClientMsg` 增 `declareKong{tile}`；`GameView` 增 `declareOptions`（我可展示的牌面，
     手牌恰好 3 张）、`declared`（全场已展示 `seat+tile`，对手明牌渲染用）、`mustDiscard`
     （我本回合必须打出的牌面）——南昌恒为空数组。
   - **状态机**：`Game.declaredKongs: Map<tile, {seat}>`；`discard()` 拒绝声明者打冻结牌、
     拒绝他人不打 `mustDiscard`；被展示牌面的响应窗口**收窄**（他家仅 `hu`、声明者仅预填
     `gang` 且不进 `awaiting`），无人可胡则立即杠成立；`advanceTurn()` / `doGangDraw()` 摸到
     本家自己挂起的牌面 → `autoGangDeclared()` 立即自动杠 + 掷骰补牌。
   - **冻结不影响胡牌**：`gzBuildWin` 用完整手牌（三张展示牌照常参与），只过滤**用到冻结牌面
     的吃牌组合**（`claimOptionsFor` 里 `chiOptions` 过滤）。
   - **计分零新增**：杠成立走既有 `gzGangs`（2 分）；精包 / 全包（§5.6）与抢杠等路径不变。

## 6. 校验方式

项目已移除自动化测试与回归脚本（2026-10-15），改为**编译校验 + 人工验证**：

```
npm run typecheck   # 全量类型检查（tsc --noEmit），必须零报错
npm run build       # 客户端构建；本机 WorkBuddy 安全 shim 会拦 vite 清 dist，需 NODE_OPTIONS="" 绕过（与本项目无关）
npm run start       # 起服务端，按规则文档人工验证
```

**人工验证清单（照规则文档逐条过）**：

| 场景 | 期望 |
|---|---|
| 建房 | 首页玩法卡片出现「赣州冲关麻将」，建房后房间角标显示该玩法 |
| 翻精 | 庄家掷骰后中央翻开 1 张正精；牌墙该墩上张为明牌 |
| 海底 | 摸到正精墩前一墩仍无人胡牌 → 和局，直接进入精分结算 |
| 有精限制 | 手上有精牌时平胡按钮不出现；精吊 / 七对 / 杠开可胡 |
| 抢杠 | 补杠时其余三家弹出抢杠胡按钮；被抢则补杠撤回、不计杠分 |
| 杠后补牌 | 杠后弹「掷骰补牌」，按点数和从牌墙尾倒数第 S 墩补牌 |
| 一炮多响 | 多人可胡时不提前结算，近出牌者先点胡则其胜；近者过则远者得 |
| 抄庄 | 第一轮四家打出同一张牌 → 结算时庄家 −30、闲家各 +10 |
| 结算 | 面板显示精分/冲关/胡牌分/杠分/交叉与直付明细；四家之和为 0 |
| 接庄 | 胡牌者下一局坐庄；和局则庄家连庄 |
| 报杠·展示 | 手有三张同牌时控件区出现「展示 3 张 X」；展示后该三张亮明、不能点出 |
| 报杠·强制出牌 | 持有该牌面的家轮到出牌只能打它（点别的报「必须先打出」）；没有的家摸到后同样强制 |
| 报杠·第 4 张 | 被强制打出时其他家只弹「胡」（无碰/吃/杠），声明者杠自动成立并掷骰补牌、+2 杠分 |
| 报杠·自摸第 4 张 | 声明者自己摸到 → 立即自动杠 + 补牌，无需点任何按钮 |
| 报杠·仍可胡 | 展示三张还在手时声明者仍能胡（含该刻子的牌型照常结算） |
| 报杠·南昌不受影响 | 南昌对局无「展示」按钮，`declareKong` 消息被拒 |

> 结算算式可用规则文档 §7.4 的示例在真机对局中复核（自摸 3 家各付胡牌分 + 交叉结算，合计恒为 0）。

## 9. 已知边界

- `rules/ganzhou.ts` 的 `score.settle`（南昌形状）为显式抛错的占位——南昌 `SettleInput`
  无法表达「12 精位逐家持有」，赣州结算走 `score.settleGz`（引擎直连）。后续把 `settle`
  泛型化（P6）可消除此占位。
- 补牌定位的「牌墙尾」= **可摸区尾部（正精墩前缘）**而非物理牌墙末端——物理末端已是海底
  预留区，不可摸。
